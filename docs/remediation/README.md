# Home Eats remediation plans

Agent-executable plans for the security, App Store, and architecture issues
found in the October 2026 review of this repo. Each plan is self-contained:
an agent should be able to pick up one file, read it, and ship it as a single
PR without reading the others (dependencies are called out explicitly).

## Execution order

Work strictly top to bottom within a phase. Phase 1 is security and comes
first. Phase 2 is the minimum required to submit 1.0 to the App Store.
Phase 3 is post-1.0 hardening and can be scheduled freely.

## Conventions for agents

Read these before starting any plan.

### Scope and PRs
- **One plan = one branch = one PR.** Branch from the repo's default branch
  (`claude/app-creation-qn2e51` at time of writing — confirm with
  `git ls-remote --symref origin HEAD`). Name the branch
  `claude/<plan-id>-<short-slug>`, e.g. `claude/s2-sms-invite-abuse`.
- Do only what the plan's **Steps** say. If you find an adjacent problem,
  write it in the PR description under "Follow-ups", don't fix it.
- Tick the plan's **Acceptance criteria** checkboxes in the PR description,
  not in this file. Update the status column in the table above in the same PR
  (`Done (#PR)`).
- Steps marked **[HUMAN]** need a person with dashboard access (Render,
  Twilio, Google Cloud, Anthropic Console, App Store Connect). Don't try to do
  them; list them in the PR description under "Needs a human".

### Backend (`backend/`)
- Node ≥ 18, Express 4, Prisma 6 (Postgres), Zod 4, CommonJS.
- Every async route goes through `lib/asyncHandler.js`.
- Schema changes need a new migration in `backend/prisma/migrations/` named
  `YYYYMMDDHHMMSS_<snake_case>/migration.sql`. Generate it with
  `npx prisma migrate dev --name <name>` against a local Postgres, or write
  the SQL by hand to match existing migrations if no database is available.
  Never edit an already-applied migration.
- After S0 lands, run `npm test` in `backend/` before every push. Before S0,
  at least run `node --check` on every changed file.
- The server won't start without `DATABASE_URL` (`index.js` calls
  `prisma.$connect()` before listening). For route-level tests, follow S0's
  pattern rather than starting the real server.

### iOS (`HomeEats/`)
- SwiftUI and SwiftData, iOS 17+. The `.xcodeproj` is generated by XcodeGen
  from `project.yml` and is not checked in.
- **Linux agent sessions have no Swift toolchain.** The only compiler check
  is the `iOS Build` GitHub Action (`.github/workflows/ios-build.yml`), which
  runs on push to `claude/**` branches. Push, then check the run before
  marking an iOS plan done. Keep Swift changes small and conservative because
  you can't run them locally.
- Network calls go through `HomeEats/Services/AccountsAPIClient.swift`
  (`send`, `sendNoContent`, `sendRaw` helpers). Add new endpoints there,
  following the existing method style.
- Name collisions: this codebase has its own `Section` type; use
  `SwiftUI.Section` in views (see commits `9edd27f` and `26896ed`).

### Comments and style
- Match the surrounding code. Existing comments are long and narrative;
  new comments should explain *why* in a sentence or two, not retell history.

### Definition of done for every plan
1. All acceptance criteria met.
2. Backend tests pass (after S0) and the `iOS Build` action is green if Swift
   changed.
3. `backend/README.md` updated if an endpoint, environment variable, or
   deploy step changed. New environment variables are added to
   `backend/.env.example` with a comment.
4. PR description lists any **[HUMAN]** steps still outstanding.
